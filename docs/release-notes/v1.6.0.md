## librouting v1.6.0 — LRXP exchange-plane records in the filter DSL (issue #81)

librouting 1.6.0 ships the LRXP exchange-plane filter DSL surface
asked for in [issue #81](https://github.com/TES286-org/librouting/issues/81)
(ROADMAP "LRXP exchange-plane filter DSL surface"). The filter DSL
now exposes the scope-1 records a route carries under the private
`LrExchangePlaneRecords` attribute, behind the `exchange-plane`
feature (off by default), so an operator can adjust `local-pref` /
`MED` based on sender-reported feasibility hints, policy intent,
and origin attestation. The eleven new `RouteFieldKind::Lrxp*`
variants are a breaking change for downstream `match`
exhaustiveness, so the bump is minor per
[`docs/RELEASE-PLAN.md`](../RELEASE-PLAN.md) §1; the C ABI surface
is unchanged.

### New features

**LRXP exchange-plane filter DSL surface** (`policy`, feature
`exchange-plane`). The filter DSL now exposes the scope-1 records a
route carries under the private `LrExchangePlaneRecords` attribute,
behind the `exchange-plane` feature (off by default). An operator
can adjust `local-pref` / `MED` based on the sender-reported
feasibility hints, policy intent, and origin attestation:

- `bgp.lrxp.verified` (Bool) — true when the route carries a
  verified LRXP record set. The single bool an operator gates on
  when a policy should apply only to LRXP-carrying routes.
- `bgp.lrxp.partial_transit` (Bool) — true when the store is
  partial-transit forwarding material (design §7).
- `bgp.lrxp.hint.rank` / `damp_fom` / `igp_cost` (Int) — the
  scope-1 feasibility hint (design §5.1). `rank` is the sender's
  best-path rank (1 = sender's best); the canonical idiom is `if
  bgp.lrxp.hint.rank > 1 then { bgp.local_pref = 50; }` to
  deprioritise poor repair candidates.
- `bgp.lrxp.policy.role` / `import_digest` / `export_digest` (Int
  / String / String) — the scope-1 policy intent (design §5.2).
  The digests are lowercase hex so two sessions can compare filter
  fingerprints with `==`.
- `bgp.lrxp.origin.origin_as` / `max_valid_len` / `expiry` (Int) —
  the scope-1 origin attestation (design §5.3).

The surface lives behind the `exchange-plane` feature (off by
default); `lr-policy` gains an `exchange-plane = ["bgp",
"lr-bgp/exchange-plane"]` feature so the typed accessors can decode
the private record store. `lr-policy::lrxp` is the accessor module.
The fallback (issue #81 requirement: a filter that adjusts
`local-pref` based on `bgp.lrxp.hint.rank` no-ops on a non-LRXP
peer) is built into the accessors — a route with no
`LrExchangePlaneRecords` attribute reads every int field as `0`,
every bool as `false`, every string as empty, so the canonical
idiom evaluates its condition to false and the local-pref write
does not fire.

`RouteFieldKind` gains twelve `Lrxp*` variants (always present on
the enum so downstream `match` exhaustiveness is stable across
feature configurations); the parser dispatch and the eval dispatch
are `#[cfg(feature = "exchange-plane")]`-gated, with a
`#[cfg(not)] _ =>` fallback so a feature-less build rejects
`bgp.lrxp.*` at parse time with `UnknownBgpField` and the
exhaustive matches stay compilable. The `FilterContext` trait gains
twelve `lrxp_*` methods with default implementations that delegate
to `lr_policy::lrxp`, so every existing embedder inherits the
correct behaviour without code changes.

### Compatibility

**Breaking change (Rust API).** The eleven new
`RouteFieldKind::Lrxp*` variants are a breaking change for
downstream `match` exhaustiveness — a downstream `match` on
`RouteFieldKind` that lacks a wildcard will fail to compile. Per
`docs/RELEASE-PLAN.md` §1 and the v1.3.0 / v1.4.0 / v1.5.0
precedent, this ships as a minor bump. The `api-surface` CI gate
catches the accidental kind.

**No C ABI change.** No new `lr_*` symbols, `ABI_VERSION` stays at
2, `lr_filter_context_t` is untouched. The new `FilterContext`
trait methods carry default implementations that delegate to
`lr_policy::lrxp`, so every existing embedder inherits the correct
behaviour without recompiling.

**Feature-gated.** The LRXP surface is off by default; a build
without `--features exchange-plane` is byte-identical to 1.5.0 and
rejects `bgp.lrxp.*` at parse time. The exchange-plane prototype is
explicitly experimental per `docs/RELEASE-PLAN.md` §1 ("What is not
public API"); its wire format rides IANA experimental code points
pending an RFC 7120 early allocation.
