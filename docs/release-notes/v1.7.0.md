## librouting v1.7.0 — BGP AIGP attribute in the filter DSL (RFC 7311)

librouting 1.7.0 ships the RFC 7311 "Accumulated IGP Metric"
attribute in the filter DSL (ROADMAP "Per-protocol route
attributes and an external conversion corpus"). The filter DSL now
exposes `bgp.aigp` so an operator can prefer lower-metric paths
within an AIGP administrative domain. The new
`RouteFieldKind::BgpAigp` variant and the new `AttrType::Aigp`
discriminant are breaking changes for downstream `match`
exhaustiveness, so the bump is minor per
[`docs/RELEASE-PLAN.md`](../RELEASE-PLAN.md) §1; the C ABI surface
is unchanged.

### New features

**BGP AIGP filter DSL surface** (`bgp`, `policy`, `cli`). The
filter DSL now exposes the RFC 7311 "Accumulated IGP Metric"
attribute so an operator can prefer lower-metric paths within an
AIGP administrative domain:

- `bgp.aigp` (Int, read-only) — the accumulated IGP metric (the sum
  of every type-1 TLV's 8-byte value in the attribute's TLV stream).
  `0` when absent or set to zero; the wire value is `u64` and the
  DSL's `int` is `i64`, so a value exceeding `i64::MAX` saturates
  (practical IGP metrics are far below `i64::MAX`). The canonical
  metric-comparison idiom is `if bgp.aigp < 100 then accept;`.
- `defined(bgp.aigp)` distinguishes "absent" from "set to zero" — a
  present value of `0` (or an empty value field) reports `true` on
  `defined` and `0` on read, exactly as BIRD's `bgp_aigp` does.

`lr-bgp::path::well_known::Aigp(pub u64)` is the typed view; its
decoder walks the attribute's TLV stream, sums every type-1 TLV's
8-byte big-endian value (the defensive choice for the malformed
"multiple type-1 TLVs" case, matching the attribute's "accumulated"
semantics per RFC 7311 §3.4.3), skips unknown TLV types (RFC 7311
§3 p5: "an AIGP TLV that is not understood MUST be preserved"), and
returns `None` on a malformed stream. The codec stores the raw
attribute bytes verbatim in `PathAttribute::value`, so unknown TLVs
round-trip byte-for-byte. `AttrType::Aigp = 26` joins the
`AttrType` enum; the attribute is optional non-transitive.

`lr-policy::bgp::{aigp, has_aigp}` are the helper pair the filter
DSL reads through. AIGP is deliberately **not** fused by the
peephole pass's `BranchFieldIntCmp` fast path — its read parses a
TLV stream (not a single `get_u32_be`), so fusing would not save
the allocation the fast path exists to avoid. Both comparison forms
run the unfused `read_route_field` path.

The BIRD translator renames `bgp_aigp` to `bgp.aigp`. The corpus
case `tests/corpus/bird/bgp-aigp-metric-filter.conf` exercises both
arms of the canonical metric-comparison idiom so the converter
round-trips the filter body through `bgp.aigp` and the daemon
loader accepts the generated TOML.

### Compatibility

**Breaking change (Rust API).** The new `RouteFieldKind::BgpAigp`
variant and the new `AttrType::Aigp` discriminant are breaking
changes for downstream `match` exhaustiveness — a downstream
`match` on either enum that lacks a wildcard will fail to compile.
Per `docs/RELEASE-PLAN.md` §1 and the v1.3.0–v1.6.0 precedent, this
ships as a minor bump. The `api-surface` CI gate catches the
accidental kind; this cut clears the `AttrType::Aigp` semver debt
the scan first surfaced.

**No C ABI change.** No new `lr_*` symbols, `ABI_VERSION` stays at
2, `lr_filter_context_t` is untouched. The new `FilterContext`
trait methods (`bgp_aigp`, `bgp_has_aigp`) carry default
implementations that delegate to `lr_policy::bgp`, so every
existing embedder inherits the correct behaviour without
recompiling.

**BIRD compatibility.** `bgp_aigp` filters translate to `bgp.aigp`
with no semantic shim. `defined(bgp_aigp)` survives verbatim.
