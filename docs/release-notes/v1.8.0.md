## librouting v1.8.0 — BGP AGGREGATOR attribute in the filter DSL (RFC 4271 §5.1.7)

librouting 1.8.0 ships the RFC 4271 §5.1.7 AGGREGATOR attribute in
the filter DSL (ROADMAP "Per-protocol route attributes and an
external conversion corpus"). The filter DSL now exposes
`bgp.aggregator.asn` and `bgp.aggregator.speaker` so an operator
can write aggregation-aware policy. The two new
`RouteFieldKind::{BgpAggregatorAsn, BgpAggregatorSpeaker}` variants
are a breaking change for downstream `match` exhaustiveness, so the
bump is minor per [`docs/RELEASE-PLAN.md`](../RELEASE-PLAN.md) §1;
the C ABI surface is unchanged. The typed `aggregator()` accessor
on `lr-bgp::path::PathAttributes` already existed; this release
wires it into the filter DSL.

### New features

**BGP AGGREGATOR filter DSL surface** (`policy`, `cli`). The filter
DSL now exposes the RFC 4271 §5.1.7 AGGREGATOR attribute — the
`(AS, IP)` pair a BGP speaker stamps onto a route when it
summarises a less-specific across several more-specifics — so an
operator can write aggregation-aware policy:

- `bgp.aggregator.asn` (Int, read-only) — the aggregator's AS number
  (`0` when absent or set to zero). The canonical aggregation-aware
  idiom is `if defined(bgp.aggregator.asn) && bgp.aggregator.asn ==
  64512 then accept;`.
- `bgp.aggregator.speaker` (Ip, read-only) — the aggregator's
  speaker IPv4 address (`false` when absent, mirroring `bgp.next_hop`
  / `bgp.originator_id`'s absent representation; gate with
  `defined(bgp.aggregator.asn)` before reading).
- `defined(bgp.aggregator.asn)` distinguishes "absent" from "set to
  zero" — a present value of AS 0 (rare but legal) reports `true` on
  `defined` and `0` on read. Both components are present together or
  absent together, so `defined(bgp.aggregator.speaker)` reports the
  same presence; `asn` is the canonical probe.

`lr-policy::bgp::{aggregator, aggregator_asn, aggregator_speaker,
has_aggregator}` are the helper quadruple the filter DSL reads
through. The typed `aggregator()` accessor on
`lr-bgp::path::PathAttributes` already existed — it accepts both
the 6-byte (2-byte-AS) and 8-byte (4-byte-AS) wire forms, and
ingress reconciles AS4_AGGREGATOR (type 18, RFC 6793) into the
canonical type-7 tag, so a single read sees the resolved value
regardless of the peer's AS-width capability.

AGGREGATOR is deliberately **not** fused by the peephole pass's
`BranchFieldIntCmp` fast path — its read decodes the `Aggregator`
struct (a length check + two fixed-size copies, not a single
`get_u32_be`), so fusing would not save the allocation the fast
path exists to avoid (mirrors the AIGP decision). Both comparison
forms run the unfused `read_route_field` path.

The BIRD translator renames `bgp_aggregator` to `bgp.aggregator.asn`
(the canonical presence probe). The corpus case
`tests/corpus/bird/bgp-aggregator-filter.conf` exercises both arms
of the canonical aggregation-aware idiom so the converter
round-trips the filter body through `bgp.aggregator.asn` and the
daemon loader accepts the generated TOML.

### Compatibility

**Breaking change (Rust API).** The two new
`RouteFieldKind::{BgpAggregatorAsn, BgpAggregatorSpeaker}` variants
are a breaking change for downstream `match` exhaustiveness — a
downstream `match` on `RouteFieldKind` that lacks a wildcard will
fail to compile. Per `docs/RELEASE-PLAN.md` §1 and the v1.3.0–v1.7.0
precedent, this ships as a minor bump. The `api-surface` CI gate
catches the accidental kind.

**No C ABI change.** No new `lr_*` symbols, `ABI_VERSION` stays at
2, `lr_filter_context_t` is untouched. The new `FilterContext`
trait methods (`bgp_aggregator_asn`, `bgp_aggregator_speaker`,
`bgp_has_aggregator`) carry default implementations that delegate
to `lr_policy::bgp`, so every existing embedder inherits the
correct behaviour without recompiling.

**BIRD compatibility.** `bgp_aggregator` filters translate to
`bgp.aggregator.asn` — the canonical probe for `defined()` (both
components are present together or absent together, so the presence
check is faithful). `defined(bgp_aggregator)` survives verbatim.
